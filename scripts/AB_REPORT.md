# skyRopeV2 组件 A/B 验证报告

> 目的：在把 12 小时级别的训练重新押上去之前，用**受控小实验**验证各项先进算法/组件是否
> (1) 跑得通、数值稳定；(2) 真的更快；(3) 在同等算力下真的更好。
>
> 方法要点：固定 **真实 token 预算**（不是固定 step，避免 padding/装箱带来的不公平）、
> **等墙钟时间**对比（决策真正关心的口径）、笔记本 GPU 会热降频所以用**交错重复取中位数**、
> 用第二个随机种子测定**噪声底**。

数据：`dataset/pretrain_t2t_mini.jsonl` 前 20000 条（≈394 万 token），验证集为该切片之后的 512 条。
模型：hidden 768 / 8 层 / MoE 4 专家 / seq 340 / bs 16（除特别说明）。
脚本：`scripts/ab_bench.py`（`--suite speed|quality`、`--tokens`、`--wall_seconds`、`--repeats`、`--seed`）。

---

## 1. 噪声底与学习率基线

| 实验 | val loss | 说明 |
|---|---|---|
| base (seed 42) | 4.5525 | AdamW 5e-4 |
| base (seed 7) | 4.5343 | **噪声底 ≈ ±0.018** |
| AdamW lr 2.5e-4 | 4.6098 | 偏低 |
| AdamW lr 5e-4 | 4.5525 | **最优** |
| AdamW lr 1e-3 | 4.6318 | 偏高 |

结论：基线 AdamW 的 5e-4 已接近最优（U 型），因此后面 Muon 的优势不是"基线被调低了"造成的。

## 6. 结论（采用 / 暂缓 / 不可用）

| 组件 | 可行性 | 速度 | 质量（等 token） | 结论 |
|---|---|---|---|---|
| MoE `permute` 调度 | ✅ | −18% step 时间 | 与原实现数值等价（diff=0） | **采用** |
| 序列 packing | ✅ | +82% tok/s | −0.25，但等时间 **−0.37** | **采用** |
| Muon + AdamW（批量 NS） | ✅ | +35~55% step 时间 | **−0.70** | **采用** |
| top-2 × 半宽专家（等激活 FLOPs） | ✅ | 最快，显存 −0.6G | **−0.22**，参数 −43% | **采用** |
| fused AdamW | ✅ | −8% | — | 采用（一行） |
| wd=0.1 | ✅ | — | 未测（当前代码是 0） | 建议采用 |
| aux-free 路由均衡 | ✅ 机制生效 | −5% | −0.01（噪声内） | 暂缓（需长跑验证） |
| 共享专家 | ✅ 可跑 | 慢 | 未测 | 暂缓 |
| WSD 调度 | ✅ | — | 预算截断下无法公平判定 | 真实训练中评估 |
| CSA/HCA 层（seq 340） | ✅ | 全 CSA +29%，默认混合 +4% | −0.05（≈2×噪声） | 保持默认；长上下文再评估 |
| torch.compile | ❌ 无 Triton（Windows） | — | — | 不可用（可试 `pip install triton-windows`） |

### 组合后的收益（实测）
- 等墙钟 7 分钟：val loss **4.2964 → 3.3122（−0.98）**
- bs32 真实吞吐：**12,075 → 21,188 tok/s（+75%）**
- 显存 8.8G → 6.2G；参数量 140.1M → 80.4M
- mini 语料每 epoch：约 5.7h → **约 3.3h**

## 7. 局限（不要过度解读）
1. 所有质量结论都来自 **300 万 token / 7 分钟**量级的早期训练；Muon 的优势通常在早期最大，
   长跑后差距可能收窄，需要在真实长跑里复核（建议 5000 万 token 后对比一次）。
2. packing 的 −0.25 是"跨文档注意力"造成的：文档之间只有 EOS 分隔、没有重置注意力。
   如果后续想进一步压榨，可加**按文档的 block-diagonal mask**（`ab_bench.py` 已有 3D 加性掩码通路）。
3. Muon 的开销来自 Newton-Schulz 的 FLOPs（对 [2432,768] 这类矩阵，NS 迭代的中介矩阵是 m×m），
   与 batch 无关；top-2 半宽（1216）把 NS 成本降到约 1/4，这是"stack"比"packed+muon"更快的原因。
4. 训练时 SWA 层是**全因果**注意力（滑窗只在带 KV cache 的推理路径生效），所以 CSA 层在短序列
   训练阶段是纯额外开销（KV 列数 +25% 加 4 个额外投影），收益只在长上下文/推理。
5. 热降频在笔记本上很明显，跨 session 的绝对耗时不可比；本报告的速度数字均来自**交错重复中位数**。

# 第二批验证（"更先进方法"专项）

协议同上：固定 **300 万真实 token**、bs16、seq340、seed 42，噪声底 ±0.018。
基线换成本轮最优组合 `stack` = packed + Muon(batched) + permute + top-2×半宽专家 = **val 3.7298**。

| 候选（在 stack 基础上加） | val loss | Δ | ms/step | 参数量 | 判定 |
|---|---|---|---|---|---|
| **stack（基线）** | **3.7298** | — | 391 | 80.4M | 采用 |
| + MTP 多 token 预测（深度1, w=0.3） | 3.7363 | +0.007 | 547 | 90.8M | ❌ 无收益 +40% 时间 |
| + z-loss(1e-4) + logit soft-cap(30) | 3.7579 | +0.028 | 414 | 80.4M | ⚠️ 默认关，长跑备用 |
| + Muon ns_steps=3 | 3.7453 | +0.016 | 436 | 80.4M | ⚠️ 质量中性（更新幅度减半），无速度收益 |
| + MLA（KV 低秩压缩 + 解耦 RoPE） | 4.4305 | **+0.70** | 358 | 86.7M | ❌ 短序列容量损失大 |
| + deep-thin（512×16 层） | 3.8956 | +0.17 | 652 | 96.9M | ❌ 又慢又差 |
| + 细粒度 MoE（8 专家 top-3 宽810） | 3.7292 | −0.001 | 566 | 100.2M | ❌ 零收益 +45% 时间 |
| + 共享专家（top1×1216 + shared×1216） | 3.8683 | +0.14 | ~440 | 95.3M | ❌ 更差 |

**结论：架构级的"更先进"项在这个规模/序列长度下全部不划算。** 有效增益集中在优化器（Muon）、
数据效率（packing、词表）、工程（permute 调度）三条线上。

## torch.compile（系统层面）
- `pip install triton-windows` 成功（3.8.0），净化环境变量后**单测可编译并跑通**（loss 与 eager 一致）。
- 但在真实训练上下文里仍然抛 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc1`
  —— 根因是**中文用户名**导致部分环境变量/路径含非 UTF-8 字节，triton 读取时崩溃。
- 判定：**本机不可靠**，需要 compile 时建议在 WSL2/Docker 里跑（仓库已有 Dockerfile）。

## 词表扩容（已完成并验证）
- 训练 24000 词表 → `model_tok24k/`，解码往返 OK、special token id 与旧词表一致（bos=1, eos=2, image_pad=12）。
- 压缩率：6400→208.2 tok/doc，24000→144.2 tok/doc，**比值 0.692（省 30.8% token）**。
- 可采用；注意 lm_head 每 token 计算量上升，综合净省约 13~20%。

## 规模判断（最重要的一条）
Chinchilla 最优点 ≈ 20 token/参数；本模型 80.4M 激活 → **需要约 16 亿 token**：

| 语料 | token | 相对最优点 | 21.2k tok/s 下每 epoch |
|---|---|---|---|
| mini（1.27M 文档） | 2.5 亿 | 15.7%（欠训 6.4×） | 3.3 h |
| **全量 pretrain_t2t.jsonl（8.47M 文档）** | **16.7 亿** | **≈100%** | **21.9 h**（配 24k 词表约 15 h） |

→ **下一轮应该直接上全量语料**，这是所有优化里回报最大的一条；mini 跑 2 epoch 只有最优点 1/3 的数据量。
